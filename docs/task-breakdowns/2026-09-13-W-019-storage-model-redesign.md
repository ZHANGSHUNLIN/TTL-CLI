## 任务清单

### T-019-01 统一存储模式解析和配置

- **目标**：将客户端活动模式收敛为 `local`/`cloud`，实现命令行、workspace、全局配置
  的固定优先级和兼容错误。
- **输入**：需求基线、现有 `internal/config` 和 `internal/client/cli/root.go`。
- **输出**：模式解析器、配置字段校验、帮助文本和单次覆盖行为。
- **依赖**：无；但需先完成方案评审中的远程字段确认。
- **验收**：默认值为 local；workspace 覆盖全局；命令行只影响当前命令；旧值明确拒绝并提示新模式；
  cloud 缺少地址或凭据时失败且不回退 local。
- **检查**：配置包单测、CLI 参数回归、敏感信息日志检查。

### T-019-02 客户端 SQLite 与 cloud 打开边界

- **目标**：让 `internal/client/app.OpenStorage` 只创建本地 SQLite 或远程 API storage，
  普通命令注入单一 `core/storage.Storage`。
- **输入**：T-019-01 的解析结果、现有 `internal/storage/sqlite` 和 `internal/client/remote`。
- **输出**：local/cloud 初始化、关闭和错误映射；移除 sync/bbolt 作为普通 storage 的入口。
- **依赖**：T-019-01。
- **验收**：local 无网络也能运行；cloud 只发 API 请求；任一初始化失败都可观察且不自动
  切换；关闭不会泄漏连接。
- **检查**：客户端单测、httptest cloud 集成测试、`go test -race`。

### T-019-03 服务端租户 SQLite 管理

- **目标**：把 `StorageManager` 的租户句柄从 bbolt 切换为每租户 SQLite 文件，并保证
  路径隔离、连接复用、关闭和删除前置检查。
- **输入**：T-019-02 的共享 storage 契约、现有 `internal/server/tenant` 和 API 测试。
- **输出**：`tenants/<user-id>/data.sqlite` 布局、新格式 schema 初始化/前向版本升级、WAL 和并发设置。
- **依赖**：T-019-02。
- **验收**：两个租户互不可见；重启后数据可读；重复请求复用句柄；关闭后无锁文件残留；
  删除前先关闭并保留备份或隔离副本。
- **检查**：tenant/API 集成测试、并发读写测试、服务重启 smoke test。

### T-019-04 旧格式拒绝与租户生命周期

- **目标**：拒绝旧 bbolt/旧 SQLite 输入，并实现租户关闭、备份/隔离和删除前置检查。
- **输入**：T-019-03 的目标 schema、旧格式检测规则和运维删除约束。
- **输出**：不兼容错误、旧文件保护、租户删除前的关闭与备份/隔离流程；不改动 `users.json`。
- **依赖**：T-019-03；方案评审必须先确认不兼容错误和租户删除边界。
- **验收**：旧格式被拒绝且不读取、转换、覆盖或删除；租户删除先关闭句柄并保留备份或
  隔离副本；删除失败时源目录仍可恢复。
- **检查**：旧格式样本单测、路径保护测试、临时目录删除故障注入和恢复演练。

### T-019-05 文档、回归和交付证据

- **目标**：同步配置示例、部署布局、不兼容说明和 W-019 阶段证据，确认 W-020 的边界未
  被实现改动侵入。
- **输入**：前四项实现与测试结果。
- **输出**：更新 `docs/server-deployment.md`、测试记录、验收记录和 owner code review。
- **依赖**：T-019-01 至 T-019-04。
- **验收**：`go test ./...`、集成测试、CLI 回归、`go vet ./...` 和 `git diff --check`
  结果可追溯；文档明确 local/cloud、SQLite、不兼容策略和 W-020 边界。
- **检查**：按项目验证脚本执行并记录版本、命令和结果。
