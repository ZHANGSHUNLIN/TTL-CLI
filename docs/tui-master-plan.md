# TTL TUI 总体设计与长期路线图

状态：提案，作为后续评审、拆解和实现的长期基线

版本：v0.1

日期：2026-09-12

## 1. 文档目标

本文是 TTL TUI 的总体设计，不是单个迭代的任务说明。它定义：

- TUI、CLI 和 CI 的最终职责边界。
- 产品希望具备的完整能力集合。
- P0、P1、P2、P3 优先级和当前进度。
- 页面、导航、交互、数据和服务层的长期约束。
- 从当前工程到目标形态的分阶段实现顺序。
- 每个阶段的验收标准、风险和暂不采用的方案。

本文与 [TTL 产品方向与使用形态](ttl-product-direction.md) 配套使用。本文件更具体，涉及 TUI 的能力、交互和实施路线时，以本文为准。

## 2. 产品结论

TTL 不是只有 TUI，而是三个入口组成的本地优先工具：

```text
CLI       快速操作、脚本、SSH 和 CI
快速选择器  搜索一条资源、打印结果，用完即退
完整 TUI   浏览、预览、编辑、整理和管理
```

推荐入口：

```bash
ttl add key "value"
ttl search "keyword" --json
ttl pick docker --print
ttl ui
```

完整 TUI 负责长时间操作，快速选择器负责短时间取用，CLI 负责可组合和非交互场景。三者必须操作同一套 core/service，不允许分别实现一套业务规则。

## 3. 设计原则

### 3.1 以取用效率为第一目标

TTL 的主要价值是“在需要时快速找到并使用内容”，不是让用户维护复杂的知识库结构。搜索、预览和取用的路径必须短于传统笔记软件。

### 3.2 逐步披露复杂能力

主界面只展示高频操作。同步、加密、审计、工作日志和高级设置通过命令面板或独立页面进入，不占用默认视图。

### 3.3 可逆和可解释

删除、覆盖、同步和批量操作都必须说明影响范围。危险操作默认不执行，失败时保留用户上下文，尽可能提供恢复路径。

### 3.4 CLI 和 CI 是一等公民

TUI 不能改变已有 CLI 的核心语义。所有核心操作都应支持非交互调用、稳定退出码和机器可读输出。

### 3.5 本地优先，远端可选

没有配置远端时，TUI 必须完整支持本地工作流。网络、API Key 或同步服务不可用时，不能阻塞本地资源的查看和编辑。

## 4. 优先级和进度定义

### 4.1 优先级

| 优先级 | 含义 | 发布要求 |
| --- | --- | --- |
| P0 | 核心闭环，不具备则产品不可用 | 首个公开可用版本必须完成 |
| P1 | 高频效率和稳定性能力 | P0 稳定后优先完成 |
| P2 | 高级管理、同步和扩展能力 | 根据真实用户反馈推进 |
| P3 | 长期候选或生态能力 | 不承诺排期，需重新评审 |

### 4.2 进度状态

- `现有`：当前工程已经提供能力，但可能需要接入 TUI。
- `重构依赖`：已有实现，但需要先抽取 service 或调整契约。
- `待实现`：设计已确定，尚未编码。
- `候选`：列入长期能力地图，尚未承诺实现。
- `不纳入`：当前产品方向明确排除。

能力地图中的“当前进度”描述的是代码或基础能力是否存在，不代表 TUI 已经可以使用。阶段交付状态单独维护，只有完成对应验收证据后才允许标记为“已完成”。

## 6. 产品入口设计

### 6.1 `ttl ui`：完整 TUI

适用于需要浏览、比较、编辑或整理多条资源的场景。启动后进入终端 alternate screen，退出时恢复原终端内容。

默认首页是资源浏览页，不是工作日志、审计或设置页。

### 6.2 `ttl pick`：快速选择器

适用于用户知道大致内容，想快速取出一条资源的场景。它是短生命周期的 TUI：输入搜索词、选择资源、打印结果后退出。系统剪贴板和默认程序打开属于后续扩展。

建议行为：

```bash
ttl pick [query]
ttl pick docker --print
```

`ttl pick` 不应打开完整设置、工作区管理或同步页面。它必须启动快、界面小、快捷键少、退出干净。P0 只保证 `--print`，`--copy` 和 `--open` 不属于当前阶段。

### 6.3 普通 CLI

CLI 继续承担以下职责：

- 单次资源增删改查。
- Shell 和 CI 调用。
- 导入导出、加密、迁移和服务端运维。
- 在没有可用终端时执行操作。

### 6.4 原生弹窗

原生系统级弹窗暂列 P3。短期内优先实现终端内快速选择器，因为它能复用 TUI、CLI 和 service，跨平台成本更低。未来如果 `ttl pick` 已经验证高频使用，再评估常驻进程和全局快捷键。

```text
ttl ui

│   ├── 搜索和过滤
│   ├── 资源详情
│   ├── 编辑资源
│   ├── 标签管理
│   └── 批量操作
├── 工作区
│   ├── 列表
│   ├── 切换
│   ├── 创建
│   └── 删除
├── 同步
│   ├── 连接状态
│   ├── 变更预览
│   ├── 冲突处理
│   └── 执行结果
```

### 7.1 默认资源浏览页

```text
┌ TTL  ·  workspace: default  ·  42 resources ──────────────┐
│ Search: docker                                  [filtered] │
├──────────────────────┬────────────────────────────────────┤
│ docker-build          │ docker build -t app .              │
│ docker-compose-prod   │                                    │
│ docker-cleanup        │ tags: docker, ops                  │
│ nginx-config          │ updated: 2026-09-12 10:30          │
│                      │ type: command                      │
├──────────────────────┴────────────────────────────────────┤
│ / search  Enter view  e edit  t tags                         │
│ d delete  w workspace  : commands  ? help  q quit          │
└────────────────────────────────────────────────────────────┘
```

布局要求：

- 资源列表是主要焦点，默认可以只使用键盘完成操作。
- 详情区域显示摘要或完整内容，不能因为长文本改变列表尺寸。
- 当前工作区、搜索条件和结果数量始终可见。
- 终端宽度不足时，详情区域可以折叠为详情页，但不能产生文字重叠。
- 标签、更新时间和资源类型是辅助信息，不抢占 key 的可读性。

### 7.2 详情页

详情页显示：

- key 和资源类型。
- 完整 value，可滚动、可换行或显示原始格式。
- 全部 tags。
- 创建时间、更新时间和最近操作。
- 可执行动作：编辑、标签、重命名和删除。复制、打开属于后续外部集成能力。

详情页不自动进入编辑状态，避免误修改。后续增加复制和打开后，操作完成仍应保留详情页上下文。

### 7.3 编辑页和弹窗

编辑内容时使用单独的表单状态：

- key 编辑和 value 编辑分离。
- 短内容使用内置输入框。
- 长内容可以调用 `$EDITOR`。
- 标签使用可增删的输入控件。
- 保存前显示变更摘要。
- `Esc` 取消，未保存时再次确认。

删除、覆盖、同步应用和工作区删除使用 modal confirmation。modal 只处理当前动作，不承载多级导航。

### 7.4 工作区页面

显示工作区名称、当前标记、数据库路径、存储类型、资源数量和状态。切换前如果有未保存编辑，必须先处理编辑状态；普通浏览状态下切换不应要求重复确认。

### 7.5 同步页面

同步页面默认是预览，不是立即执行：

```text
Local only:   3
Remote only:  2
Conflicts:    1

按方向查看变更 → 选择 pull/push → 确认应用
```

当前阶段不实现 CRDT。冲突必须显示本地和远端摘要，并明确将覆盖哪一侧。

## 8. 交互规范

### 8.1 全局按键

| 按键 | 行为 |
| --- | --- |
| `/` | 进入全局搜索 |
| `Esc` | 关闭 modal、返回上一层或清空搜索 |
| `Enter` | 查看当前资源或确认当前表单 |
| `e` | 编辑当前资源 |
| `t` | 管理标签 |
| `d` | 删除并进入确认 |
| `w` | 打开工作区选择 |
| `s` | 打开同步预览 |
| `:` | 打开命令面板 |
| `?` | 显示当前页面帮助 |
| `q` | 退出或返回 |

在文本输入状态下，字符按键优先输入，不抢占全局快捷键；`Esc`、`Ctrl+C` 和 `Ctrl+S` 等控制键保持一致语义。

### 8.2 命令面板

命令面板用于低频功能和快捷键发现，例如：

```text
Search commands
> Switch workspace
  Export resources
  Show operation history
  Sync preview
  Toggle color mode
```

命令面板不能代替可见的高频操作，也不能成为所有功能唯一入口。

### 8.3 状态反馈

每个异步操作都应显示：

- 当前操作名称。
- 进行中状态。
- 成功或失败结果。
- 失败时的下一步建议。

状态消息显示在底部区域，不覆盖资源内容。错误不能只输出到日志后让界面无响应。

### 8.4 空态和错误态

| 状态 | 界面行为 |
| --- | --- |
| 没有资源 | 显示添加第一条资源的操作入口 |
| 搜索无结果 | 显示搜索词和清除过滤操作 |
| 数据库未初始化 | 提供初始化或配置路径提示 |
| 数据库被占用 | 说明锁定原因和重试操作 |
| 保存失败 | 保留编辑内容，允许重试或导出草稿 |
| 远端不可用 | 保持本地可用，显示同步失败原因 |
| 终端过窄 | 折叠详情或切换单栏视图 |
| 非交互终端 | 退出 TUI，提示使用 CLI 或 `--json` |

## 9. 技术架构

当前仓库已规划 client、server、core 和 storage 边界；TUI 应作为客户端入口加入该结构，而不是直接调用服务端 handler。

```text
cmd/ttl
  ├── internal/client/cli
  └── internal/client/tui
          ↓
  internal/client/application
          ↓
  internal/core/resource
  internal/core/storage
          ↓
  internal/storage/sqlite
  internal/storage/bbolt
  internal/client/remote
```

### 9.1 包职责

| 包 | 职责 |
| --- | --- |
| `internal/client/tui` | Bubble Tea model/update/view、页面、modal 和键盘交互 |
| `internal/client/application` | 资源、搜索、工作区、同步等用例编排 |
| `internal/client/cli` | Cobra 参数、stdout/stderr、退出码和 CLI 兼容入口 |
| `internal/client/remote` | `/api/v1` HTTP 客户端 |
| `internal/core/resource` | 资源、标签、历史和日志领域类型 |
| `internal/core/storage` | 存储接口和数据访问契约 |
| `internal/storage/sqlite` | 默认 SQLite 实现 |
| `internal/storage/bbolt` | bbolt 实现和服务端租户数据库实现 |
| `internal/client/sync` | 差异计算、预览和 push/pull 用例 |

TUI 不依赖 Cobra 命令输出；CLI 不依赖 TUI 渲染状态。两者只共享 application/core 契约。

### 9.2 应用服务契约

以下接口是长期方向，具体命名可以在编码阶段调整，但职责不能回退到入口层：

```go
type ResourceService interface {
    Search(ctx context.Context, query SearchQuery) (SearchResult, error)
    Get(ctx context.Context, key string) (Resource, error)
    Create(ctx context.Context, input CreateResourceInput) (Resource, error)
    Update(ctx context.Context, key string, input UpdateResourceInput) (Resource, error)
    Delete(ctx context.Context, key string) error
    AddTags(ctx context.Context, key string, tags []string) (Resource, error)
    RemoveTag(ctx context.Context, key, tag string) (Resource, error)
}

type WorkspaceService interface {
    List(ctx context.Context) ([]Workspace, error)
    Current(ctx context.Context) (Workspace, error)
    Switch(ctx context.Context, name string) error
}

type SyncService interface {
    Plan(ctx context.Context) (SyncPlan, error)
    Apply(ctx context.Context, plan SyncPlan, direction SyncDirection) (SyncResult, error)
}
```

服务方法必须返回结构化结果和可判断的错误。TUI 负责将结果转换成视图，CLI 负责将结果转换成文本或 JSON。

## 10. CLI/CI 接口契约

### 10.1 命令输出模式

| 能力 | 入口 | 入参 | 出参 | 错误行为 |
| --- | --- | --- | --- | --- |
| 搜索 | `ttl search` | query、tag、type、format | 文本列表或 JSON 数组 | 无结果返回空结果，不视为系统错误 |
| 查看 | `ttl get` | key、format | 资源详情 | key 不存在返回业务错误 |
| 快速选择 | `ttl pick` | query、`--print` | 选中资源或 value | 非交互环境必须使用 `--print` 或直接失败；`--copy`/`--open` 后续评估 |
| 同步预览 | `ttl sync --dry-run` | direction、format | 变更计划 | 网络错误返回系统错误，不执行写操作 |
| 导出 | `ttl export` | type、format、output | 文件或 stdout | 文件不可写返回系统错误 |

### 10.2 非交互约束

- `--non-interactive` 下禁止数字选择、确认提示和读取 stdin。
- `--json` 输出不得混入进度文本、调试信息或本地化提示。
- stdout 只输出结果，诊断信息写入 stderr。
- 退出码至少区分：成功、参数错误、资源不存在、冲突/拒绝、系统错误。
- 删除、同步应用和覆盖操作必须显式传入 `--confirm` 或 `--apply`。

### 10.3 远端 HTTP 契约

TUI 不直接调用服务端 handler；远端操作统一经过 `internal/client/remote`。现有 `/api/v1` 契约保持兼容：

| 路径 | 方法 | 入参 | 出参 | 错误语义 |
| --- | --- | --- | --- | --- |
| `/api/v1/resources` | GET | 可选 `q` 查询参数 | `ResourceDTO[]` | HTTP 500 / `code=2` 表示服务错误 |
| `/api/v1/resources` | POST | `key`、`value`、可选 `tags` | 创建后的 `ResourceDTO` | key 为空或重复返回 `code=1` |
| `/api/v1/resources/{key}` | PUT | `value` | 更新后的 `ResourceDTO` | key 不存在返回 404 / `code=1` |
| `/api/v1/resources/{key}` | DELETE | 无 | 空数据 | key 不存在返回 404 / `code=1` |
| `/api/v1/resources/{key}/tags` | POST | `tags[]` | 更新后的 `ResourceDTO` | 资源不存在或 tags 为空返回 `code=1` |
| `/api/v1/resources/{key}/tags/{tag}` | DELETE | 无 | 更新后的 `ResourceDTO` | 资源不存在返回 404 / `code=1` |
| `/api/v1/resources/{key}/rename` | POST | `new_key` | 更新后的 `ResourceDTO` | key 为空或资源不存在返回 `code=1` |
| `/api/v1/audit/stats` | GET | 无 | `AuditStats` | 服务错误返回 HTTP 500 / `code=2` |
| `/api/v1/history` | GET | 可选 `limit` | `HistoryRecord[]` | 服务错误返回 HTTP 500 / `code=2` |

所有需要认证的请求携带 `Authorization: Bearer <api-key>`。TUI 的网络错误必须转换为可恢复状态，不得导致本地页面退出或覆盖本地数据。

## 11. 数据模型和兼容性

### 11.1 P0 核心字段

第一阶段保持当前核心结构：

```text
key
value
tags
created_at
updated_at
```

不因为 TUI 引入新的必填字段，现有 SQLite、bbolt 和 HTTP 数据应继续可读。

### 11.2 P1 可选字段

后续可以增加：

```text
kind       text / url / command / code
favorite   bool
archived   bool
```

新增字段必须有默认值、迁移策略和旧数据兼容测试。

### 11.3 内容策略

内容模型暂时保持“文本 value + 标签”。Markdown 预览、代码高亮和类型推断属于 P1/P2 的展示能力，不改变 P0 的存储契约。附件、关联资源和知识图谱暂不进入核心模型。

## 12. P0-P3 实施路线

### P0：可用闭环

目标：新用户可以安装、启动、搜索、查看、编辑和安全删除资源，同时保留 CLI/CI 能力。

实施步骤：

1. 冻结资源、搜索结果、错误和 CLI JSON 契约。
2. 从 `command/` 和全局 `db.Stor` 调用中抽取 application service。
3. 增加 key、value、tag 的搜索服务，补齐 value 全文搜索。
4. 为 CLI 增加 `search`、`list`、`--json`、`--non-interactive` 和稳定退出码。
5. 实现 TUI 主壳、资源列表、搜索框和详情预览。
6. 实现资源编辑、标签管理、删除确认和状态反馈。
7. 实现 `ttl pick` 快速选择器及 `--print` 输出。
8. 覆盖空态、错误态、窄终端、异常退出和 CLI/TUI 数据一致性。

P0 完成标准：

- 不阅读长文档也能启动并添加第一条资源。
- 只记得 value 片段也能找到资源。
- 主要操作可只用键盘完成。
- TUI 不改变现有 CLI 数据语义。
- CI 可使用 JSON、stdin/stdout 和退出码完成自动化。
- 删除和保存失败不会静默丢失数据。

### P1：高频效率和可维护性

目标：让用户可以长期使用，而不只是偶尔查询。

实施步骤：

1. 增加排序、过滤、收藏、归档和资源类型。
2. 增加工作区切换和工作区状态面板。
3. 增加 `$EDITOR`、多行编辑、草稿恢复和编辑变更摘要。
4. 增加批量打标签、批量归档和批量删除确认。
5. 增加标签统计、操作历史和基础审计页面。
6. 完善导入导出、加密和密钥状态的 TUI 操作。
7. 增加跨平台终端兼容、无颜色模式、鼠标辅助和可访问性检查。

P1 完成标准：

- 数十到数百条资源仍能快速浏览和过滤。
- 长内容编辑不依赖复杂的命令转义。
- 工作区、加密和备份等运维能力不需要手工修改配置文件。
- 所有批量和危险操作都有明确影响预览。

### P2：高级管理和同步体验

目标：在本地体验稳定后提供可控的远端能力。

实施步骤：

1. 把远端 API 客户端完全收敛到 `internal/client/remote`。
2. 实现同步连接状态和完整变更预览。
3. 提供批量同步结果、失败重试和可导出的同步报告。
4. 在 TUI 中展示本地/远端差异和简单冲突处理。
5. 增加保存搜索、搜索历史、最近使用和资源热度。
6. 评估 Markdown 渲染、代码高亮和类型化预览。

P2 完成标准：

- 没有远端时本地功能完全可用。
- 同步默认预览，应用前明确确认。
- 网络失败不会破坏本地数据。
- 同步结果可被 CLI、TUI 和 CI 以同一结构读取。

### P3：长期候选能力

目标：根据真实使用数据决定是否扩大产品边界。

候选内容：

- 离线变更队列和后台同步。
- 版本向量、变更日志和 CRDT。
- 原生系统级弹窗和全局快捷键。
- 本地 Web UI。
- 插件或脚本扩展机制。
- 外部应用集成。

以下内容不属于 P3 候选，而是当前明确不纳入：

- AI 自然语言操作。
- AI 工作总结。
- 多人协作和 SaaS。
- 原生移动端。
- 复杂知识图谱。

## 15. 风险和控制

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| TUI 直接复用命令输出 | 行为难测、界面脆弱 | 先抽取 application service，TUI 只消费结构化结果 |
| 全屏 TUI 过于复杂 | 用户只想取一条内容时反而变慢 | P0 同时实现 `ttl pick`，主界面保持资源优先 |
| 全局存储状态污染测试 | 页面切换和并发操作不稳定 | 通过构造函数注入 service/storage，逐步消除 `db.Stor` |
| SQLite/bbolt 行为分叉 | 用户数据和迁移风险 | 保持 Storage 契约，增加跨后端兼容测试 |
| 同步误删数据 | 数据损失 | 默认预览，显式 `--apply`，记录同步计划和结果 |
| 终端兼容性差 | 跨平台无法使用 | P0 做窄终端、异常退出和多平台手工验收 |
| 功能不断膨胀 | TUI 变成复杂后台系统 | P3 只列候选，新增能力必须有真实场景和优先级 |
| CLI 和 TUI 语义漂移 | CI 脚本不稳定 | 共用 service，黑盒回归固定机器可读契约 |

## 16. 待决策项

## 17. 最终形态摘要

```text
P0：可用闭环
  CLI + CI + ttl pick + 基础 ttl ui

P1：长期好用
  高级搜索、编辑、工作区、批量操作、安全和发布体验

P2：可控扩展
  同步预览、远端管理、历史搜索和内容展示增强

P3：重新评估
  CRDT、后台同步、原生弹窗、Web UI 和插件

明确不做
  AI、SaaS、多人协作、移动端、复杂知识图谱
```

最终原则：**TUI 是主要体验，CLI/CI 是稳定底座，快速选择器是高频捷径；所有入口共享同一套业务服务和数据契约。**
