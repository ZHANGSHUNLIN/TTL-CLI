# 后端服务移出 ttl-cli 仓库

日期：2026-09-18
状态：adopted
任务：W-021

## 背景

`ttl-cli` 同时维护客户端和 `ttl-server`，包括后端 API、认证、租户存储、用户管理、CI 制品与部署脚本。后续将由专门的后端服务工程承担这些职责，继续双份维护会导致协议、实现和发布流程漂移。

## 决定

当前仓库只维护 `ttl` 客户端。删除 `cmd/ttl-server`、`internal/server`、服务端发布任务、部署脚本和只依赖内置 handler 的测试。

保留 `internal/client/remote`、cloud 配置与同步客户端，它们通过 HTTP 使用外部后端服务。当前 `/api/v1` 客户端契约保持不变；独立后端的源码、数据、认证、租户隔离、部署和发布均不属于本仓库。

本记录替代 `2026-09-12-separate-client-server-layout.md` 中“两端源码同仓”部分、`2026-09-13-server-independent-delivery-baseline.md` 的本仓发布基线，以及 `2026-09-13-server-tenant-sqlite.md` 的本仓实现归属。

## 备选方案

- 保留后端代码但停止发布：仍会留下可编译的第二实现和维护责任，无法形成清晰边界。
- 把后端移入本仓子 module：可以隔离依赖，但仍由本仓维护，不符合专门后端服务工程的方向。
- 同时删除 cloud 与 sync：会破坏客户端远程能力，超出“移除后端实现”的目标。

## 影响

收益是仓库、CI 和 release 只面向客户端，后端可以独立演进。代价是本仓库不再提供一键自建后端，也不能独立完成真实端到端 cloud 验证。

协议兼容成为跨工程责任。本仓库以 mock HTTP 测试保护客户端请求契约；新后端准备好后，应建立独立的契约或端到端流水线。删除源码不删除任何仓库外部署或数据。

## 验证

- 检查后端入口、包、workflow job 和交付脚本已删除。
- 构建并完整验证 `ttl` 客户端。
- 运行 `internal/client/remote` 的 HTTP mock 测试。
- 人工核对 README、项目导览和工程边界文档。
