# TUI、CLI 与快速选择模式的交互策略

- 状态：adopted（基础 TUI / W-007 范围；W-013 于 2026-09-13 通过独立需求和方案评审后追加为阶段承诺）
- 日期：2026-09-12
- 关联设计：[TUI 总体设计与长期路线图](../tui-master-plan.md)
- 关联评审：[TUI、CLI 与客户端边界设计评审与整改复核](../reviews/2026-09-12-tui-client-boundary-design.md)（`PASS`，仅基础 TUI / W-007 范围）

## 问题与背景

当前 TTL 主要通过命令行完成查看和操作，能力可用但不适合复杂浏览、预览和编辑。引入 TUI 可以缩短多条资源之间的操作路径，但如果只保留全屏 TUI，会损害脚本、SSH 和无 TTY 自动化场景；如果直接做系统级弹窗，跨平台和生命周期成本又较高。

CLI 和 TUI 是同一个 `ttl` 客户端的两种交互形式。两者使用相同的账户、API Key、业务服务、存储契约和远端 API；相对于服务端没有身份或数据所有权上的区别。CI 不是独立客户端，只是 CLI 可能运行的一种自动化环境。

产品还明确了以下边界：TUI 是主要交互形式，CLI 必须保留；快速选择器是短生命周期的 TUI 模式；工作日志是低优先级审计模块；暂不引入 AI、CRDT、后台同步、浏览器或原生系统弹窗。当前也不提供账户间资源分享、协作者、资源级权限或多人实时编辑。同一 API Key 被多个进程或设备使用只是需要防御的数据一致性风险，不把产品边界扩大为多人协作。

本记录最初只对基础 TUI / W-007 范围采用“两种交互形式、同一核心”的策略。CLI/TUI 共用核心和服务端不区分交互形式是已确认基线。2026-09-13 的范围变更由 W-013 独立需求、技术方案和方案评审承接；本记录不替代其具体契约。

## 采用范围（基础 TUI / W-007）

采用“两种交互形式、同一核心”的策略；以下内容中只有第 1 项的本地基础 TUI 部分属于 W-007 交付承诺：

1. `ttl ui` 首期提供本地资源浏览、搜索、预览、编辑、标签和安全删除；工作区、同步和其他管理能力需按基线单独确认。
2. `ttl pick` 作为短生命周期的快速选择模式，是否进入首期和是否提供 `--print` 由独立需求确认；该独立确认现已完成，v1 不提供 `--print`。
3. CLI 继续提供核心命令；开发阶段允许直接调整其行为，稳定退出码、JSON、stdin/stdout 和非交互约束属于候选增强。
4. CLI、完整 TUI 和快速选择模式只共享 application/core/storage 契约，不互相解析文本输出，也不复制业务规则。
5. 系统级弹窗、CRDT、后台同步和 AI 保持候选或明确不纳入，须基于真实使用数据重新评审。

## 备选方案

### 仅保留全屏 TUI

优点是界面集中、实现入口少。缺点是单条资源取用变慢，并且不能替代 CLI 的无 TTY 调用，因此不采用。

### 直接实现原生系统弹窗

优点是全局快捷入口体验好。缺点是需要常驻进程、剪贴板、权限和三平台适配，无法先验证核心工作流，因此延后到 P3 候选。

### 迁移到 Node.js + TypeScript

优点是部分 TUI 组件生态较丰富。缺点是引入运行时和发布复杂度，现有 Go 存储、API 和客户端单二进制优势需要重新建设；当前 TUI 需求不足以抵消迁移成本，因此保留 Go。

## 收益与代价

收益：高频用户有完整 TUI 和快速选择两种路径；自动化用户继续使用 CLI；业务规则集中后，各种交互模式可以共享测试和数据语义。

代价：需要先抽取 application service 和显式存储生命周期；TUI 需要额外处理终端恢复、窄窗口和跨平台输入；交互模式和契约数量增加后需要持续维护行为测试。

## 风险与控制

- TUI 复杂度膨胀：默认首页只保留资源浏览，高级模块通过命令面板和独立页面逐步披露。
- CLI/TUI 语义漂移：禁止 TUI 解析 CLI 文本，所有入口共用 service，并以黑盒测试锁定 JSON 和退出码。
- 单条取用体验变差：通过独立 W-013 提供 `ttl pick` v1；`--print` 仍作为后续扩展评估，不阻塞基础 `ttl ui`。
- 远端或同步影响本地使用：本地优先，网络错误只能影响同步操作，不能阻塞本地浏览和编辑。

## 验证方式

若方案经基线确认，后续在对应里程碑中分别验证：

- CLI 候选契约在独立需求确认后，通过无 TTY 黑盒验证 JSON、stdin/stdout 和退出码。
- `ttl pick --print` 只有在后续独立需求批准后，才验证无 TTY 下的显式输出模式；当前 v1 不提供该选项。
- `ttl ui` 的资源增删改查、搜索和标签操作与 CLI 共享同一数据语义。
- macOS、Linux/SSH、Windows Terminal 的终端恢复和窄窗口验收通过。

若这些指标不能满足真实使用场景，再单独创建新的决策记录评估原生弹窗、Web UI 或其他交互形态。
