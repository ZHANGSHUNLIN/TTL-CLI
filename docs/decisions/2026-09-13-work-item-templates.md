# 采用任务模板和文档槽位的创建策略

日期：2026-09-13
状态：adopted
任务：W-015

## Context

手工创建任务经常遗漏研发阶段文档。仅生成一条 Markdown 任务记录无法保证需求、设计、评审、WBS、测试和验收有位置可填写。

## Decision

新任务通过 dashboard 模板创建；七种类型共享六个文档槽位，类型只决定默认阶段清单和提示内容。创建从 `Inbox` 开始，不自动填写真实结论、不自动提交 Git。服务端预检所有路径并在进程锁内提交，失败时清理本次文件并恢复清单。

## Consequences

- 新任务可立即在看板上看到完整研发产物链路。
- 轻量任务也会有六个骨架文件，需要在文档中明确“不适用”，避免流程歧义。
- 多文件 rename 无法提供跨进程数据库事务；实现通过备份、锁和回滚降低风险，外部并发编辑仍需人工避免。
