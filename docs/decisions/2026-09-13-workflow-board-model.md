# 采用任务类型与研发阶段元数据

日期：2026-09-13
状态：adopted
关联任务：W-014

## 背景

看板原先只有五个生命周期状态，无法表达 feature、bugfix、docs 等任务类型，也无法显示需求、方案、WBS、实现和测试等阶段进度。把这些阶段直接做成看板列会让不同类型任务出现大量不适用的列。

## 决策

保留 `Inbox`、`Doing`、`Review`、`Blocked`、`Done` 作为统一生命周期状态；在 `WORK_ITEMS.md` 中增加可选任务元数据：类型、优先级、当前阶段、阶段清单、父任务、依赖、产物、阻塞原因和下一步。阶段清单由任务明确提供，不根据标题自动推断。看板负责解析和展示，不自动修改任务文件或生成阶段产物。

## 影响

- feature、bugfix、docs、chore 等任务可以使用不同阶段清单。
- 旧任务缺少新字段时仍能加载，只显示兼容默认值。
- 看板页面可以显示当前阶段和阶段进度，但生命周期状态的流转规则不变。
- 阶段元数据由任务拥有者维护，页面暂不提供编辑入口。

## 未采用方案

- 不把八个研发阶段扩展成固定看板列。
- 不根据任务标题或文件路径自动判断类型和阶段。
- 不引入远程项目管理服务或新的持久化数据库。
