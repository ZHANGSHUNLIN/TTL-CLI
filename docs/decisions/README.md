# Decision Records

这里记录本项目的重要设计决定。它不是任务清单，也不是用户文档；它回答的是：
为什么这样做、还考虑过什么、这个选择带来了什么影响。

## 什么时候需要写

以下改动需要新增或更新一条决策记录：

- 选择或更换核心技术方案。
- 修改数据库、配置、文件格式或同步协议。
- 改变 CLI 用户可见行为、默认值或契约变更策略。
- 引入安全、迁移、隐私或数据丢失风险。
- 放弃一个看起来合理、以后可能被重新提出的方案。
- 修改本地开发流程或人工审核规则。

以下改动通常不需要写：

- 拼写、格式、注释或 README 的小修小补。
- 局部 Bug 修复，且原因和影响已经能从代码或测试看清。
- 不改变行为的简单重构。
- 只更新依赖补丁版本，且没有迁移或调用方影响。

## 文件命名

使用日期加短标题：

```text
docs/decisions/2026-09-11-use-local-work-items.md
```

状态只保留三种：

- `proposed`：还在考虑。
- `adopted`：已经采用。
- `rejected`：明确不采用。

## 审核规则

任务进入 `Review` 时，检查是否触发了“什么时候需要写”的条件。如果触发，必须新增或更新对应决策记录；如果没有触发，可以在任务备注里写 `决策：无需记录，原因：...`。

一条决策记录通过审核需要满足：

- 背景说明能解释为什么需要决定。
- 决定写清当前采用的方案。
- 备选方案至少列出一个真实考虑过的选择。
- 影响同时写清收益和代价。
- 状态与实际代码或流程一致。
