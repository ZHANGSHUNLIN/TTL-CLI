# 需求分析：本地与云端存储模式收敛

任务：W-019
类型：feature
状态：需求已确认，方案评审通过，已进入编码

## 问题与用户目标

当前客户端把 `sqlite`、`local`/`bbolt`、`cloud` 和 `sync` 混在同一个 `--storage`
选择中，导致用户无法判断普通命令实际访问哪个数据源，也让存储实现和数据同步互相
耦合。

本任务只负责存储模式收敛：普通命令要么访问本地数据，要么访问远程数据。数据同步、
版本向量、CRDT、冲突处理和同步触发策略拆到 W-020《设计本地与云端数据同步及冲突
处理》，不在本任务内定义或实现。

## 目标

1. 客户端只向用户暴露 `local` 和 `cloud` 两种存储模式，当前命令始终只使用其中一端。
2. `local` 表示本地 SQLite 数据；`cloud` 表示远程服务数据；两者提供一致的资源语义。
3. 用户可以配置多个命名远程 profile，每个 profile 包含地址和凭据引用；当前应用或当前
   workspace 只激活其中一个，普通命令不需要重复输入连接参数。
4. `bbolt`、裸 `sqlite` 和 `sync` 不再作为用户可选的存储模式。
5. 新版本不兼容旧 bbolt/旧 SQLite 文件；切换模式不会静默复制、转换、覆盖或删除另一端数据。

## 范围

### 纳入范围

- `local` / `cloud` 两种存储模式及当前数据源切换。
- 本地 SQLite 存储的默认路径、workspace 配置和生命周期。
- 远程 API 地址、活动账户、凭据引用和连接校验。
- 远程服务作为 cloud 存储端的资源访问契约和生命周期。
- CLI 帮助、配置校验、单次命令覆盖和错误提示。
- 现有资源、标签、历史、审计和日志能力在两种存储模式下的兼容行为。

### 不纳入范围

- 本地与远程之间的数据同步、双向合并、`push`/`pull` 策略和定时同步。
- 版本向量、操作日志、outbox、server revision 和幂等同步协议。
- OR-Set、Multi-Value Register、tombstone 或其他 CRDT 规则。
- 同一资源并发修改、删除与修改冲突以及冲突解决界面。
- 多设备离线编辑和实时协作。

同步相关内容统一由 W-020 负责：
[W-020 同步需求文档](2026-09-13-W-020-local-cloud-data-sync.md)。

## 用户流程

### 选择本地存储

1. 用户将当前存储模式设置为 `local`。
2. 普通资源、标签、历史和审计命令只访问本地 SQLite。
3. 本地模式不要求网络、远程地址或 API Key 可用。
4. 本地数据库不可用时，命令返回明确的本地存储错误，不自动切换到 cloud。

### 选择云端存储

1. 用户配置一个或多个远程 profile，并为当前 workspace 选择一个活动 profile。
2. 客户端验证地址、健康状态和凭据。
3. 用户将当前存储模式设置为 `cloud`。
4. 普通资源、标签、历史和审计命令只访问远程服务。
5. 远程不可用或认证失败时，命令返回明确错误，不自动切换到 local。

### 切换存储模式

1. 用户显式切换当前模式，或为单次命令提供覆盖参数。
2. 切换只改变普通命令的访问目标，不自动复制、删除或覆盖另一端数据。
3. 不提供旧数据迁移操作；需要使用新版本时由用户创建新的 SQLite 数据库。模式切换不
   触发复制、转换、删除或覆盖。

## 业务规则

- `local` 和 `cloud` 是当前数据源的二选一；一次命令不能同时把两端作为普通存储使用。
- `sync` 不是存储类型；同步能力和冲突规则由 W-020 单独定义。
- 本地存储统一使用 SQLite；用户不可再选择 `bbolt` 作为新数据存储。
- `cloud` 通过远程服务 API 访问，客户端不直接打开远程数据库文件。
- 存储初始化和关闭由客户端命令生命周期显式管理，失败必须返回可识别错误。
- 切换模式不改变另一端数据，不自动执行迁移或删除。
- 旧 bbolt/旧 SQLite 文件不是新版本的有效输入；发现旧文件时必须明确报错并停止，不得
  自动转换或覆盖。
- API Key 不进入仓库、命令历史、普通日志或未加密的示例配置。

## 异常与边界场景

| 场景 | 期望结果 |
| --- | --- |
| 未配置 cloud 地址或凭据 | 选择 cloud 时给出配置错误，不修改 local 数据 |
| local 数据库无法打开 | 返回本地存储错误，不自动请求 cloud |
| cloud 网络不可用 | 返回远程连接错误，不自动读取 local |
| cloud 认证失败 | 返回认证错误，保留当前模式，不降级到 local |
| 切换 local/cloud | 只改变访问目标，不复制、删除或覆盖另一端 |
| 旧 bbolt 或旧 SQLite 数据存在 | 明确提示不兼容，要求指定新的 SQLite 路径，不读取或修改旧文件 |
| 单次命令覆盖模式 | 只影响当前命令，不修改默认模式 |
| 使用 `sync` 作为 storage 值 | 参数校验失败，并提示同步属于 W-020 独立能力 |

## 验收标准

- [ ] CLI 帮助和配置只暴露 `local`、`cloud` 两种存储模式。
- [ ] `bbolt`、裸 `sqlite` 和 `sync` 作为 storage 值时明确拒绝，并提示新模式或独立同步能力。
- [ ] local 模式只访问本地 SQLite；cloud 模式只访问远程服务。
- [ ] 当前模式、workspace 规则、单次命令覆盖和优先级有文档和测试。
- [ ] 可以配置多个远程 profile，但当前应用或 workspace 只有一个活动 profile，并经过连接校验。
- [ ] 两种模式下资源、标签、历史、审计和日志命令的基本语义保持一致。
- [ ] 旧 bbolt/旧 SQLite 文件被明确拒绝，且不被读取、转换、覆盖或删除。
- [ ] 模式切换不会自动复制、删除或覆盖另一端数据。
- [ ] 本地、远程、配置缺失、认证失败和旧格式不兼容均有可观察错误。
- [ ] W-019 的实现、测试和文档不引入 W-020 的同步、CRDT 或冲突协议。

## 已确认的需求基线

以下决定作为 W-019 的需求输入，具体接口和包归属由技术方案展开：

1. **服务端存储**：服务端为每个租户维护一个独立 SQLite 文件，保持现有租户隔离；
   `users.json` 继续保存账号和 API Key，本任务不迁移账号库。
2. **配置作用域**：命令行显式 `--storage` 优先于当前 workspace 的 `storage_type`，
   workspace 未设置时使用全局 `storage.type`，都未设置时默认 `local`。单次覆盖不写回配置。
3. **远程配置**：远程名称和 API 地址可以配置多个，但当前应用或 workspace 只激活一个；
   `cloud` 命令启动时校验活动 profile，未配置或校验失败不得回退到 `local`。
4. **兼容策略**：新版本不兼容旧 bbolt/旧 SQLite 文件，不提供迁移命令或兼容窗口；旧
   文件只读保留，新版本使用新的 SQLite 路径。
5. **资源能力**：资源、标签、历史、审计和日志在 local/cloud 两种模式下继续遵循同一
   `core/storage` 语义；cloud 的数据由远程 API 提供，客户端不直接访问服务端文件。
6. **同步边界**：本地与远程的数据同步、版本记录、增量传输、CRDT 和冲突处理全部由
   W-020 负责。W-019 只提供两个稳定、互斥的数据源打开方式。

## 假设与后续确认

- W-019 以单机或少量并发的现有服务部署为目标，服务端暂不引入 PostgreSQL 或共享多租户
  SQLite；若规模或并发模型变化，另立决策记录。
- SQLite 文件名统一为 `data.sqlite` 作为新格式；现有 `data.db`/`data.bbolt` 不作为输入，
  不能按文件扩展名尝试打开或转换。
- schema 版本只服务于新格式的前向升级；租户删除的运维审批由技术方案定义。
