# `ttl pick` 快速选择模式需求

状态：candidate，未纳入当前阶段承诺
基线：[`docs/requirements/2026-09-12-capability-boundary-baseline.md`](2026-09-12-capability-boundary-baseline.md)
相关拆分：[`docs/task-breakdowns/2026-09-12-tui-scope-split.md`](../task-breakdowns/2026-09-12-tui-scope-split.md)

## 1. 问题与目标

当前用户可以通过完整的 `ttl ui` 浏览资源，也可以通过既有命令获取资源，但“记得一部分内容、选一条、把值交给下一个命令”仍缺少一个短生命周期入口。`ttl pick` 用于一次性取用本地资源：用户输入可选的搜索词，在候选中确认一条资源，命令只把该资源的 value 输出到结果流。

它是客户端中的快速选择交互，不是第三种客户端，也不替代完整的 `ttl ui`。它不修改资源，不打开设置、工作区或同步页面。

## 2. 术语与数据边界

- **资源**：只指 `ORIGIN` 类型的原始资源，字段为 `key`、`value`、`tags`、`created_at`、`updated_at`。
- **候选**：搜索结果中的一条资源。`TAG` 类型的内部索引项不能直接出现在候选列表中，也不能被单独输出。
- **query**：用户输入的一个搜索字符串。搜索规则沿用现有资源搜索规则，不在本需求中引入正则、分词或模糊评分。
- **结果流**：命令成功时的 stdout。结果流只承载选中资源的 value，便于管道消费。

## 3. 使用场景与用户流程

### 3.1 按关键词取一条资源

1. 用户运行 `ttl pick "8080"`。
2. 系统在本地资源中搜索 key、value 和 tag 包含 `8080` 的资源。
3. 只有一条候选时直接选中；多条候选时显示编号和 key，等待用户确认。
4. 用户输入候选编号后，系统将该资源的 value 写入 stdout 并成功退出。

### 3.2 不带 query 浏览并取用

1. 用户运行 `ttl pick`。
2. 系统加载全部原始资源，按确定顺序展示候选。
3. 用户选择一条或取消。

空 query 的行为是“全部原始资源”，不是“最近使用资源”；本需求不引入最近使用、收藏或排序字段。

### 3.3 脚本或管道调用

- 成功时调用方可以直接使用 `ttl pick query | next-command`。
- 交互提示、候选列表和诊断信息不得污染 stdout；它们写入 stderr。
- 没有可交互终端时命令必须快速失败，不得等待 stdin。

## 4. 功能范围

### 4.1 包含

- 命令入口：`ttl pick [query]`，query 最多一个参数。
- 本地资源搜索，匹配 key、value 和 tag。
- 零条、单条和多条候选的可观察处理。
- 多条候选中的单条选择、取消和 EOF 处理。
- 选中资源的 value 纯输出。
- 无 TTY、非法选择、存储读取失败和资源无匹配的明确失败结果。
- 与 `ttl ui` 和既有资源命令共享相同的资源定义和搜索语义。

### 4.2 不包含

- `--copy`、`--open`、编辑、删除、标签修改、批量选择或同步。
- 远端、云端、工作区切换、账号权限和网络请求。
- 修改 `get`、`add`、`update`、`del`、`tag`、`dtag` 的默认行为。
- 新的 JSON schema 或通用 CLI 机器契约；如需结构化输出，另立需求。
- 分页、候选上限、最近使用、收藏和搜索权重。

## 5. 功能与业务规则

### FR-01 命令参数

- `ttl pick`：query 为空，候选为全部原始资源。
- `ttl pick <query>`：使用一个 query 搜索候选。
- 多于一个位置参数、未知 flag 或无法解析的参数属于 `invalid_argument`，不读取资源、不进入交互。
- query 按用户传入的字符串参与匹配；大小写不影响匹配。首尾空格是否在 CLI 层去除必须在技术方案中固定，并补充测试，不能在不同入口采用不同规则。

### FR-02 搜索范围与匹配

- 只搜索 `ORIGIN` 资源；内部 `TAG` 索引项不得重复展示。
- query 非空时，只要 key、value 或任一 tag 对 query 命中，就算候选。
- 命中是大小写不敏感的子串匹配，与现有 `FindResources` 语义一致。
- query 为空时返回全部原始资源；空数据库得到零候选，并按 FR-06 的空结果约定结束。
- 搜索只读本地存储，不触发远端请求或数据同步。

### FR-03 候选顺序与展示

- 候选顺序必须稳定：先按 `created_at` 降序，再按资源 key 升序；完全相同时按 key 的字节序升序兜底。
- 多条候选按从 `1` 开始的连续编号展示；每项至少展示可区分的资源 key。
- 候选列表不得展示完整 value，避免在选择阶段泄露长文本或敏感内容。
- 候选列表、选择提示和取消提示写入 stderr；stdout 在选择成功前保持为空。
- 不实现分页或隐式截断；候选很多时仍必须保证编号与实际可选项一致。

### FR-04 选择与取消

- 只有一条候选时无需用户输入，直接选中。
- 多条候选时，用户输入 `1..N` 并确认后选择对应候选。
- `q`、`Esc`、Ctrl-C 或输入流 EOF 均表示取消；取消不输出 value。
- 空输入、非数字、超出 `1..N` 的数字均为 `invalid_choice`；命令不得把它解释为另一条资源。
- 选择完成后不再继续读取 stdin，也不重复执行搜索。

### FR-05 成功输出

- 成功时 stdout 只输出选中资源的 value，不输出 key、tag、提示、审计信息或调试信息。
- value 内容按存储内容输出；命令最多补一个终止换行，不能改变 value 中已有的换行或其他字符。
- 成功退出后，调用方可以用标准管道读取完整 value。
- 本需求不规定 JSON 输出；`--print` 是否作为显式非交互输出模式保留为开放问题。

### FR-06 失败与退出语义

下列结果必须非零退出，且 stdout 为空；具体数字由技术方案依据现有 CLI 退出码契约确定：

| 场景 | 稳定错误类别 | 额外要求 |
| --- | --- | --- |
| 无匹配 | `not_found` | stderr 包含 query，不泄露无关资源 value |
| 存储读取失败 | `system_error` | stderr 保留底层失败原因上下文 |
| 无 TTY | `interaction_required` | 在读取 stdin 前失败，不阻塞 |
| 非法参数 | `invalid_argument` | 指出参数问题 |
| 非法候选编号 | `invalid_choice` | 说明可选范围 |
| 用户取消或 EOF | `cancelled` | 与无匹配、系统错误区分 |

错误类别应能被测试或 CLI 错误映射识别，不能只依赖本地化文案。

### FR-07 数据安全与兼容性

- `ttl pick` 全程只读，不创建、覆盖、删除或修改资源、标签、历史和审计数据；本需求不记录 `pick` 审计事件。
- 不因实现 `ttl pick` 增加资源字段、改变存储格式或改变现有搜索结果。
- 既有 `ttl get` 的单条直出、多条选择、非交互歧义失败语义保持不变；可以复用规则，但不能通过修改 `get` 来隐藏 `pick` 的行为差异。
- 本地存储不可用时，不尝试切换到远端或同步服务。

## 6. 异常与边界场景

| 场景 | 预期行为 |
| --- | --- |
| 空数据库、空 query | stderr 给出空候选提示，非零 `not_found` 或约定的空结果类别；stdout 为空 |
| 空数据库、有 query | 非零 `not_found`，stderr 包含 query |
| query 命中一条 | 不读 stdin，直接输出 value |
| query 命中多条 | stderr 展示稳定编号，等待一次选择 |
| key/value/tag 同时命中同一资源 | 只展示一次 |
| 只有 TAG 内部索引命中 | 不把索引项作为候选；按对应 ORIGIN 资源规则处理 |
| value 为空字符串 | 仍可成功选择；stdout 只产生约定的终止换行 |
| value 含多行或尾随换行 | 保留内容，不输出额外标签或提示 |
| 输入 `0`、负数、超大数字 | `invalid_choice`，不输出 value |
| 输入字母或混合文本 | `invalid_choice`，不输出 value |
| 选择后 stdin 仍有内容 | 不消费后续内容 |
| 需要交互但 stdin 不是 TTY | 按无 TTY 规则快速失败，不等待交互；stdout 非 TTY 本身不构成失败 |
| 资源读取中断或存储损坏 | `system_error`，stdout 为空，stderr 保留原因 |
| 候选 key 很长或含空白 | 展示仍可区分，编号不因显示格式变化 |

空数据库的错误类别（`not_found` 或单独的空结果类别）以及 query 首尾空格处理属于实现前必须冻结的两个细节，不能由不同实现自行决定。

## 7. 验收标准

- [ ] `ttl pick` 和 `ttl pick <query>` 的参数规则、空 query 语义和非法参数行为有黑盒测试。
- [ ] 搜索测试证明 key、value、tag 的大小写不敏感子串匹配，并证明 TAG 内部索引不会重复出现在候选中。
- [ ] 测试证明候选顺序稳定，重复执行同一数据得到相同编号。
- [ ] 黑盒测试覆盖零条、单条、多条、重复命中、空 value、多行 value 和超长 key。
- [ ] 交互测试覆盖合法编号、`q`、`Esc`、Ctrl-C、EOF、空输入、非数字、越界数字。
- [ ] 成功场景断言 stdout 只有 value，提示和诊断全部在 stderr；结果可被管道消费。
- [ ] 所有失败场景断言 stdout 为空、退出非零，并能识别稳定错误类别。
- [ ] 无 TTY 测试证明命令在不读取 stdin 的情况下快速失败，不发生阻塞。
- [ ] 只读测试证明 pick 不改变资源、标签、历史、审计和存储文件。
- [ ] 既有 `ttl get` 的回归测试通过，且 W-007 基础 TUI 的行为和交付范围不受影响。
- [ ] 文档、帮助文本和错误文案遵循项目本地化规范；候选能力未被写成阶段承诺。

4. 完成独立技术方案和方案评审；评审未通过不得编码。

## 9. 开放问题与假设

### 必须在技术设计前回答

- `--print` 是否进入首期？它是否允许无 TTY 直接按 query 选择，还是只改变成功输出格式？
- 空数据库应复用 `not_found`，还是定义可被脚本区分的 `empty_result`？
- query 的首尾空格是否去除？若不去除，帮助文本和测试必须明确空格是匹配内容的一部分。

### 当前假设

- 首期不支持分页、上限、搜索评分或最近使用；所有候选均可被编号选择。
- 资源 value 是文本字符串，输出不承诺二进制安全语义。
- 该需求只描述产品行为和可观察契约，不预设 Go 包、接口、终端库、存储查询或测试实现。
