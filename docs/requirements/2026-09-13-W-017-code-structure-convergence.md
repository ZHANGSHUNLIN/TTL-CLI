# 客户端与服务端代码结构收敛需求

日期：2026-09-13  
任务：W-017  
状态：approved-and-implemented

任务类型：refactor  
优先级：P1

## Problem And Goal

当前仓库已经建立 `cmd/ttl`、`cmd/ttl-server`、`internal/client`、`internal/server`、`internal/core` 和 `internal/storage` 等目标边界，但旧结构仍与新结构并存。客户端入口仍注册顶层 `command/` 的全局 Cobra 命令，并同时依赖顶层 `models`、`conf`、`i18n` 和 `sync`；`models` 只是 `internal/core/resource` 的别名；根目录 `sync/` 与 `internal/client/sync/` 职责重叠；`db/` 仍被集成测试和服务端测试使用。

这使维护者无法仅根据目录判断代码归属，也让新增功能容易继续依赖旧包。W-003/W-004 已完成的项目导览和入口边界不能代替这次结构收敛。本需求以当前代码为事实，重新定义最终结构目标、迁移边界和行为不变规则，为后续技术设计和 WBS 提供门禁。

目标是：在不改变既有 CLI、TUI、HTTP API、数据文件和同步语义的前提下，形成唯一且可执行的代码归属规则，在一次结构切换中完成生产代码、测试和旧兼容层的统一迁移。

## Scope

### In Scope

- 明确客户端入口、客户端用例、服务端入口、服务端用例、共享领域契约和具体存储实现的唯一归属。
- 收敛资源领域类型和存储契约，使 `internal/core` 成为共享契约的唯一来源；迁移并删除仅用于转发的旧 `models` 别名。
- 收敛客户端 CLI 命令装配和命令适配层，避免新的客户端功能继续增加顶层 `command/` 与 `internal/client/cli` 的双重入口。
- 收敛同步能力的归属，区分客户端同步用例、镜像存储适配和共享存储接口，消除根目录 `sync/` 与客户端同步包的职责重叠。
- 迁移仍依赖 `db/`、全局存储或旧模型别名的集成测试、服务端测试和辅助代码；完成迁移后删除不再需要的旧门面和构造器。
- 对 `conf/`、`crypto/`、`i18n/`、`util/` 等顶层包做归属判定，并在技术设计中明确保留、下沉或拆分的理由。
- 建立可执行的架构依赖检查，阻止客户端依赖服务端、服务端依赖客户端，以及新代码重新依赖已声明淘汰的旧包。
- 更新 `PROJECT_OVERVIEW.md`、拆分方案、任务清单和相关决策记录，使文档状态与代码现状及本次一次性切换的准备/结果一致。

### Out Of Scope

- 不改变 `ttl` 或 `ttl-server` 的命令名称、参数、输出、退出码和既有交互语义。
- 不新增 TUI、CLI、同步、远端 API 或服务端业务能力；本任务只整理归属和迁移结构。
- 不修改 SQLite、bbolt、配置文件、加密文件、HTTP `/api/v1` 或同步数据格式；如技术设计发现必须迁移，须另行立项并记录决策。
- 不实现 W-010 的云端独立制品、部署、TLS、升级或回滚链路。
- 不为了目录整齐移动安装脚本、文档、测试工具或其他没有明确归属收益的文件。
- 不在没有替代实现、测试证据和回滚方式的情况下直接删除旧代码。

## Use Cases

1. **定位修改入口**：维护者根据目录和结构文档能够判断资源命令、TUI、服务端 API、同步、模型和存储应该修改在哪里，不需要在新旧目录之间猜测。
2. **新增客户端能力**：新增 CLI/TUI 能力时使用明确的客户端用例和契约，不再创建新的顶层全局命令或直接依赖服务端包。
3. **修改共享契约**：调整资源字段或存储接口时，维护者能看到所有客户端、服务端、存储和测试消费者，并能判断是否需要迁移或兼容。
4. **独立构建验证**：构建 `ttl` 时不链接服务端实现，构建 `ttl-server` 时不链接客户端命令、TUI 或旧客户端同步入口。
5. **结构回归检查**：引入新的包依赖或迁移旧包时，架构测试能够在本地检查中明确失败，而不是依赖人工发现。

## Rules

- `cmd/ttl` 是客户端唯一可执行入口，`cmd/ttl-server` 是服务端唯一可执行入口；两个入口不得互相依赖。
- 客户端、服务端和共享 core 的职责必须能从 import 方向和目录同时判断；core 不依赖客户端、服务端或具体存储适配器。
- 共享资源模型和存储接口只保留一个事实来源；别名或兼容包只能在迁移期间保留，并必须有明确的删除条件。
- 同一类 CLI 行为只能有一个命令装配入口；可复用业务逻辑不能依赖 Cobra 全局变量、全局输出或全局存储状态。
- 结构迁移必须保持既有行为、数据格式和错误边界；行为变化必须拆成独立需求，而不能借重构顺手引入。
- 一次迁移变更必须同时迁移生产消费者、测试、架构检查和文档；不能把新旧结构作为多个长期交付物保留。
- 迁移完成时必须证明无生产和测试消费者，并在同一次结构切换中删除无继续价值的旧包；目标包的单元、集成和黑盒证据必须覆盖原行为。
- 顶层辅助包的最终归属必须在技术设计中明确；未决归属不能通过继续增加 import 规避。

## Edge And Failure Cases

- **迁移产生 import cycle**：暂停整体切换，重新拆分 ownership 或提取最小共享契约；不能通过新增跨层反向依赖绕过。
- **测试仍依赖旧 `db` 或 `models`**：整体切换不得进入验收，先完成测试迁移，不能把旧包留成长期并行实现。
- **CLI/TUI 行为回归**：回滚整体结构切换，补充包级、集成和黑盒证据后再重新执行。
- **服务端误链接客户端代码**：架构依赖测试和服务端构建必须失败，整体切换不得合入。
- **发现需要数据或 API 迁移**：暂停结构重构，记录影响和恢复方案，另建迁移需求；本任务不隐式修改现有数据。
- **文档与代码状态不一致**：以代码和测试为当前行为事实，以本需求和后续方案为目标状态；在方案评审和一次性切换收口前修正文档，不把草案当作完成证据。
- **删除旧包后发现外部调用方**：回滚整体切换并确认兼容边界；不能通过无记录的破坏性删除处理。
