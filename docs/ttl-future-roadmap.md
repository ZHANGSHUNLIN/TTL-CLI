# TTL 后续能力规划

状态：候选规划，不构成交付承诺
基线：[`docs/ttl-product-direction.md`](ttl-product-direction.md) v0.2

本文集中记录当前基线之外的候选能力。它们用于后续复评和排序，不属于当前首期需求，也不得直接进入实现任务。

## 使用规则

- 候选能力只有在单独需求、技术设计、方案评审和工作项完成后，才能转为阶段承诺。
- 本文的顺序是规划顺序，不是排期承诺；优先级会根据真实使用反馈重新评估。
- 候选能力不得隐式新增数据字段、公共 API、客户端入口、同步语义或第三方依赖。
- 当前首期范围以 [`docs/requirements/2026-09-12-capability-boundary-baseline.md`](requirements/2026-09-12-capability-boundary-baseline.md) 为准。

## 第一组：客户端效率增强

- `ttl pick --print`、复制、打开资源和外部编辑器（`ttl pick` v1 已由 W-013 交付，扩展能力仍为候选）。
- 核心资源命令之外的 JSON、非交互模式和 stdin/stdout 管道扩展；六个核心命令由 W-012 跟踪为阶段承诺。
- 复制、打开资源、外部编辑器和草稿恢复。
- 更丰富的搜索排序、过滤、摘要、搜索历史和保存搜索。
- `kind`、`favorite`、`archived` 等资源元数据。

## 第二组：管理与发布体验

- 工作区切换、工作区状态和批量操作。
- 备份恢复、加密和密钥管理的 TUI 操作。
- Linux、macOS、Windows 的完整发布与终端体验。
- 无颜色模式、鼠标辅助和可访问性增强。
- 审计、工作日志和导入导出的完整 TUI 页面。

## 第三组：远端与同步增强

- 同步预览、批量同步结果和失败恢复报告。
- 同账户多设备的 revision、冲突检测和幂等操作。
- 离线变更队列和后台同步。
- 版本向量或 CRDT，仅在简单 revision/冲突检测不足且经过单独评审时重新考虑。

## 第四组：扩展形态

- 本地 Web UI。
- 插件或脚本扩展机制。
- 浏览器、Raycast、剪贴板等外部入口。
- 原生系统级弹窗和全局快捷键。

## 明确不纳入当前方向

- AI 自然语言操作和 AI 工作总结。
- MCP 集成。
- 原生移动端。
- 多人协作、跨账户分享、资源级权限和多人实时编辑。
- 在线 SaaS 服务。
- 复杂知识图谱、附件和复杂富文本核心模型。
