# Basic TUI Technical Design

日期：2026-09-12
任务：W-007 / T-02
需求：`docs/requirements/2026-09-12-capability-boundary-baseline.md`
状态：reviewed

## Current Behavior

`cmd/ttl` 只组装 `internal/client/cli` 的 Cobra 命令树。`internal/client/cli` 在 `PersistentPreRunE` 中解析工作区和存储配置，通过 `internal/client/app.OpenStorage` 打开一次存储并注入 `app.Service`，执行结束后关闭。W-006 已让资源增删改查和标签操作经过结构化 service；W-012 已验证 CLI 可在该边界上消费 typed error，而不是解析存储错误文本。

当前没有 `ttl ui` 子命令或 TUI 包。`app.ListResources` 只列 origin 资源，`app.FindResources` 当前匹配 key 和 tag；W-007 要求补齐 value 匹配。默认存储仍由现有 `--storage`、`--conf` 和工作区规则决定。基础 TUI 只承诺本地资源闭环，不接入 cloud、sync、工作区管理或 `ttl pick`。

## Proposed Ownership

| Area | Owner | Responsibility |
| --- | --- | --- |
| `internal/client/cli` | Cobra composition root | 注册 `ttl ui`，复用现有配置解析和 service 生命周期；拒绝机器模式及非本地存储 |
| `internal/client/tui` | TUI adapter | Bubble Tea model/update/view、资源列表、搜索、详情、编辑、标签 modal、删除确认和状态反馈 |
| `internal/client/app` | Shared client use cases | list/search/get/create/update/tag/delete、typed errors；不感知 Cobra 或终端组件 |
| `internal/core` / `internal/storage` | Shared contracts and adapters | 保持现有资源模型和 SQLite/bbolt 持久化格式；不增加 TUI 专用字段 |
| `cmd/ttl` | Product entry | 继续只调用 `internal/client/cli.Run`，不单独构造第二套 TUI 应用 |

新增依赖固定使用 `github.com/charmbracelet/bubbletea`、`github.com/charmbracelet/bubbles` 和 `github.com/charmbracelet/lipgloss` 的精确版本。依赖版本在实现开始时选择当前兼容 Go 1.25 的稳定版本，并由 `go.mod`/`go.sum` 固定；不引入 Node.js 或外部运行时。

## Interfaces

### Command contract

```text
ttl [global storage/config flags] ui
```

- `ui` 不接收位置参数。
- `--json` 或 `--non-interactive` 与 `ui` 同用时，沿用现有 machine-mode 校验返回参数错误，不启动 alternate screen。
- `--storage=sqlite` 使用当前 SQLite 工作区；`--storage=local` 或 `--storage=bbolt` 使用当前 bbolt 工作区。
- `--storage=cloud` 或 `--storage=sync` 返回可行动错误，说明基础 TUI 只支持本地存储；不得发出网络请求。
- 启动前若 stdin 或 stdout 不是终端，返回错误并提示改用 CLI。终端判断由命令 adapter 完成，model 单元测试不依赖真实 TTY。

`options` 增加三个仅用于 composition/test seam 的函数：storage opener（默认 `app.OpenStorage`）、TTY detector 和 TUI runner。`PersistentPreRunE` 先解析实际 storage type；当目标命令为 `ui` 时，按“参数/machine mode → 实际 storage type 必须是 SQLite/bbolt → stdin/stdout 必须为 TTY”的顺序完成门禁，全部通过后才调用 opener。门禁失败时 opener 调用次数必须为零。

`newUICommand` 从 command context 取得 W-006 的 `*app.Service`，把它作为接口注入 TUI runner。命令不打开或关闭第二份数据库；正常退出、初始化失败和 panic 恢复后的关闭仍由现有 `executeRoot` / `mergeCloseError` 负责。

### Application contract

TUI 消费以下已有结构化方法：

```go
ListResources() ([]app.Resource, error)
FindResources(query string) ([]app.Resource, error)
GetResource(key string) (app.Resource, error)
CreateResource(key, value string, tags []string) (app.Resource, error)
UpdateResourceValue(key, value string) (app.Resource, error)
AddResourceTags(key string, tags []string) (app.Resource, error)
DeleteResourceTag(key, tag string) (app.Resource, error)
DeleteResourceWithCleanup(key string) (app.DeleteResult, error)
```

W-007 对 `FindResources` 的 service 变更是：只遍历 `Key.Type == ORIGIN` 的资源，并按 key、value 和该 origin value 的 tag 做不区分大小写的子串匹配；TAG alias 永不作为结果返回。空 query 等同 `ListResources`。无匹配对 TUI 是正常的空结果；为保持现有调用兼容，service 可以继续返回 `ErrorNotFound`，TUI 必须把该类别映射为搜索空态而非系统错误。其他 `ServiceError` 保持 `not_found`、`conflict`、`system_error` 分类。

删除编排从 Cobra handler 收敛到 `app.Service.DeleteResourceWithCleanup`：先确认 origin resource 存在，再 best-effort 清理该 key 的 history 和 audit，最后删除资源。清理失败不阻止资源删除，`DeleteResult` 携带 `HistoryCleanupError` 和 `AuditCleanupError`；资源删除失败仍返回 `ServiceError{Kind: ErrorSystem, Operation: ErrorDelete}`。CLI 保持现有行为：仅 debug 文本模式展示清理失败；TUI 在删除成功后展示非阻塞警告。旧的分散删除编排被移除，避免出现两个业务入口。

资源 value 更新的元数据责任统一为：application 将原 `CreatedAt` 带入更新；具体 storage adapter 在成功写入时保留该创建时间并生成新的 `UpdatedAt`。SQLite 和 bbolt 都必须满足该规则；tag 更新同样不得清空时间字段。该修正不改变持久化格式。

### TUI runner and model seam

`internal/client/tui` 暴露最小入口：

```go
type ResourceService interface { /* 上述资源方法 */ }
type RunOptions struct { In io.Reader; Out io.Writer; InitialWidth int; InitialHeight int }
func Run(service ResourceService, opts RunOptions) error
```

model 持有资源快照、当前过滤词、选中项、viewport、当前页面/modal、编辑草稿、脏状态和底部状态消息。所有存储调用通过 Bubble Tea command 返回 typed message；`Update` 只处理 message 和状态迁移，便于无终端单测。`InitialWidth/InitialHeight` 只服务于无终端测试和首帧占位，真实运行收到 `WindowSizeMsg` 后始终以消息尺寸为准。首期不启动后台同步或长期 goroutine。

## Interaction And State Model

默认页为资源浏览页：顶部显示本地存储、搜索词和结果数；主体宽屏时为左侧列表、右侧详情，窄屏时只显示列表，`Enter` 进入单栏详情；底部显示当前可用快捷键和最近状态。内容预览换行并可滚动，长 value 不改变列表宽度。

| State | Entry | Keys and outcome |
| --- | --- | --- |
| Browse | 启动或操作成功后 | `j/k`、方向键选择，`Enter` 详情，`/` 搜索，`n` 新建，`e` 编辑，`t` 标签，`d` 删除，`?` 帮助，`q` 退出 |
| Search | `/` | 输入即时过滤 key/value/tag；`Enter` 保留过滤并回到 Browse；`Esc` 清空并回到 Browse |
| Detail | `Enter` | 上下键滚动长内容；`e/t/d` 进入对应动作；`Esc/q` 回到 Browse |
| Edit | `n` 或 `e` | 新建依次编辑 key、value、tags；修改仅编辑 value，标签由 Tag modal 维护；`Tab` 换字段，`Ctrl+S` 保存，`Esc` 取消 |
| Tag | `t` | 输入逗号分隔的新标签并添加；已有标签可选择后删除；`Esc` 返回 |
| DeleteConfirm | `d` | 显示 key 和 value 摘要；只有显式选择确认或输入 `y` 才删除，`n/Esc` 取消 |
| UnsavedConfirm | 脏 Edit 中 `Esc/q/Ctrl+C` | 选择继续编辑或放弃；首期不承诺跨进程草稿恢复 |
| Help | `?` | 只展示当前页面快捷键；任意 `Esc/?/q` 返回 |

在输入框聚焦时，普通字符不触发全局快捷键。`Ctrl+C` 在非脏状态立即退出，在脏编辑状态先进入未保存确认。保存前 model 校验 key 非空；标签按逗号切分、去首尾空白、去空值和去重。创建冲突保留全部草稿并聚焦 key；保存系统错误保留草稿并允许重试。

标签修改复用 `AddResourceTags` 和 `DeleteResourceTag`。每次成功写操作后重新调用当前 query 的 list/find，按 key 重新定位选中项，确保页面展示持久化后的时间和标签。删除只有在 service 成功后才从列表消失；删除失败保留当前资源和确认上下文。

## Data And Configuration

- 不改变 `resource.Key`、`resource.Value`、SQLite schema、bbolt bucket、配置文件或远端 HTTP 契约。
- CLI 和 TUI 使用同一个 `app.Service` 和同一工作区数据库；TUI 不维护缓存文件、搜索历史或草稿文件。
- `ui` 尊重现有 `--conf`、默认工作区以及显式 `--storage`。基础范围只允许解析后的 SQLite/bbolt 存储。
- TUI 展示文本从 i18n locale 读取；按键符号和资源原文不翻译。实现需同步补齐已有 locale，避免把用户可见文案散落在 model。

## Lifecycle And Failure Behavior

- Creation：Cobra pre-run 解析本地配置、打开 storage、构造一个 service；TUI runner 创建 program 并首次加载资源。
- Mutation：model 发出单次 service command；写成功后刷新资源并保留可预测选择，写失败保留屏幕上下文和草稿。删除由共享 application use case 编排清理和资源删除，两个入口不各自复制步骤。
- Cleanup：Bubble Tea program 退出并恢复 alternate screen、光标和输入模式；随后 CLI composition root 关闭 service。runner 不直接关闭 storage。
- Failure and recovery：初始读取失败显示错误页，可重试或退出；运行中读取失败保留上一份成功快照；保存/标签/删除失败不乐观移除或覆盖 UI 状态。
- Panic：runner 边界恢复 panic，尽力让 Bubble Tea 恢复终端后返回带上下文错误；service 仍由外层关闭。panic 不被当作成功。
- Concurrency：每次只允许一个 in-flight mutation；期间禁用重复提交。SQLite/bbolt 锁错误作为可观察系统错误展示。基础 TUI 不解决与第二个 `ttl` 进程的写冲突。
- Resize：`WindowSizeMsg` 重新计算布局；宽度不足时切到单栏，最小尺寸下显示简短提示而不重叠或 panic。

## Security And Compatibility

- 本地加密和文件权限继续由现有 storage adapter 负责；TUI 不记录 value、API key 或数据库路径到日志。
- 未保存内容只保存在进程内存；退出时放弃后不可恢复，确认框必须明确说明。
- CLI 默认文本、W-012 JSON schema、退出码、服务端和同步语义不变。`ui` 自身明确拒绝机器模式和远端存储。
- `ttl ui` 仅增加一个子命令；`cmd/ttl-server` 不导入 `internal/client/tui`，架构测试应锁定该边界。

## Alternatives

- 直接从 TUI 执行 Cobra 命令或解析 CLI 输出：拒绝，会复制表示层语义且无法保留 typed error 和草稿。
- 让 TUI 自己调用 storage：拒绝，会绕过 W-006 的 service 边界并让 CLI/TUI 规则漂移。
- 使用 tcell 或自研终端状态机：拒绝；项目总体设计已选择 Bubble Tea，自研输入、resize 和终端恢复成本更高。
- 首期接入 cloud/sync：拒绝；远端标签契约尚未端到端一致，也会破坏 W-007 的本地闭环边界。
- 首期加入外部编辑器、复制、打开、工作区、批量操作或跨进程草稿：拒绝；均属于后续候选。

## Test And Regression Plan

| Layer | Evidence |
| --- | --- |
| Service unit | value 全文匹配、空 query、origin-only、typed read error；现有 CRUD/tag/error 测试继续通过 |
| TUI model unit | 初始/空/无结果/错误状态，列表选择，搜索，宽窄布局，详情滚动，创建/编辑/tag，保存失败保留草稿，删除确认/失败，脏退出确认，in-flight 防重入 |
| CLI unit | root 暴露 `ui`；参数和 machine-mode 拒绝；用 fake opener/TTY detector 证明非 TTY、cloud、sync 门禁发生在 open 之前；runner error 传播；service 只由外层关闭 |
| Storage / integration | SQLite 和 bbolt 下经 TUI service 写入后可由同一 service/CLI 读取；创建、修改、标签和删除持久化；更新后 created/updated 时间语义一致 |
| CLI black-box | 现有 `./scripts/regression.sh` 不回退；用临时 HOME/conf/database 构建真实二进制，验证 `ttl ui` 无 TTY 失败且不污染 stdout 数据契约 |
| Build / static | `gofmt -s -l .`、双二进制构建、`go test ./...`、`go test ./integration_test/...`、`go test -race ./...`、`go vet ./...`、`git diff --check`、`./scripts/verify.sh` |
| Manual | macOS 和 Linux/SSH 下启动/退出/`Ctrl+C` 终端恢复；80 列及更窄单栏；中文与多行长内容；CLI/TUI 交叉观察完整 CRUD/tag |

测试 storage 和 CLI 时必须使用 `t.TempDir` 或临时 HOME/conf，不能打开用户真实 `~/.ttl`。model 测试使用 fake `ResourceService`，不得依赖真实 alternate screen 或计时 sleep。

## Rollout And Recovery

- 先实现 value 搜索和纯 model，再注册 `ui` 命令，最后补真实终端人工验收。`ttl ui` 是新增入口，不迁移现有数据。
- 若新入口验证失败，保持 W-007 为 `Doing` 或 `Review`，移除 `ui` 注册和 TUI 包即可回滚；现有 CLI 和数据库格式不需要回滚。
- W-007 只有在实现、自动检查、人工终端验收、owner code review 和本地 commit 完成后才能进入 `Done`。
